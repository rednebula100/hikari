| [CollisionChess (TAMU)](https://people.engr.tamu.edu/sueda/courses/CSCE450/2025S/projects/Darwin_White/index.html) | 잡힌 기물이 물리적으로 날아가는 연출 | 충격량 기반 연출만, 규칙은 일반 체스. |

**결론:** 성공한 변형은 ① 규칙 변경이 **하나**이고 ② 그 하나가 **잡기/전술의 본질**을 바꾸며 ③ 결과가 **눈에 보이는 순간**(폭발, 드롭, 오리)을 만든다. "충돌로 잡기"는 Dynamo·Falling Off가 재미를 검증했지만, **질량과 운동량 보존을 실제로 계산하는 체스는 찾지 못했다.** 여기에 독창성의 자리가 있다.

## 4. 추천안 상세 — 光: 충돌 체스

### 4.1 30초 규칙
1. **체스 그대로 움직인다.** 캐슬링·앙파상·승진·체크·체크메이트·스테일메이트까지 FIDE 규칙 그대로.
2. **잡는 대신 부딪친다.** 적에게 달려들면 실제 물리처럼 충돌한다. 무거운 것이 가벼운 것을 날리고, 같은 질량은 멈추고 넘겨주고(뉴턴의 요람), 가벼운 것은 튕겨 나온다.
3. **판 밖으로 나가면 제거.** 적 킹을 판 밖으로 날리면 승리. 체크 = "다음 수에 킹이 날아갈 수 있는 상태".

### 4.2 질량과 속도
| 기물 | 질량 m | 비고 |
|---|---|---|
| 폰 | 1 | |
| 나이트 | 3 | **충돌 대신 낙하 공격**: 위에서 떨어져 목표를 그 자리에서 제거(완전 비탄성 수직 충돌). 체스 고유의 '잡기'를 유일하게 유지하는 기물 → 암살자 역할. |
| 비숍 | 3 | |
| 룩 | 5 | |
| 퀸 | 9 | |
| 킹 | 10 | 가장 무겁다. 밀리기는 한다. |

- **도움닫기 속도:** 슬라이딩 기물은 출발 칸에서 목표까지의 거리 L칸을 달려 속도 v = L (칸/턴)로 부딪친다. 폰 대각·킹은 v = 1.
- **광속:** c = 8 칸/턴 (빛은 한 턴에 판을 가로지른다). 충돌은 **1차원 상대론적 탄성 충돌**(질량중심계에서 속도 반전 → 로런츠 속도 덧셈으로 복귀)로 정확히 계산. 저속에서는 뉴턴 결과와 같고, 고속에서는 차이가 난다.

| 충돌 | 뉴턴 (공격자 / 목표) | 상대론 c=8 (공격자 / 목표) | 게임상 의미 |
|---|---|---|---|
| 룩(5)→폰(1), 3칸 | 2.00 / 5.00 | 2.04 / 4.60 | 폰이 5칸 vs 5칸(반올림) |
| 비숍(3)→나이트(3), 2칸 | 0 / 2 | 0 / 2 | 뉴턴의 요람: 비숍 정지, 나이트 2칸 |
| 폰(1)→룩(5), 1칸 | −0.67 / 0.33 | −0.67 / 0.34 | 폰이 튕겨 나오고 룩은 거의 안 밀림 |
| 퀸(9)→폰(1), 4칸 | 3.20 / **7.20** | 3.28 / **6.04** | **7칸 vs 6칸 — 판 밖으로 나가는지가 갈린다** |
| 퀸(9)→폰(1), 7칸 | 5.60 / 12.60 | 6.17 / 7.86 | 뉴턴이면 광속 초과, 상대론은 c 아래 |
| 룩(5)→킹(10), 6칸 | −2.00 / 4.00 | −2.35 / 4.68 | 킹 4칸 vs 5칸 밀림 |

(위 수치는 이 문서 작성 중 실제 계산값.)

### 4.3 충돌 해석 (엔진 규칙)
- 충돌은 이동 방향의 한 직선 위에서만 일어난다(1차원). 그 직선 위의 다른 기물은 연쇄 충돌에 참여한다(아군 포함).
- 충돌 순간부터 **1턴 동안** 모든 기물이 받은 속도로 미끄러지고, 턴이 끝나면 마찰로 정지한다. 사건 기반 시뮬레이션으로 연쇄 충돌을 정확히 계산한 뒤, 최종 위치를 칸에 맞춰 반올림한다.
- 칸 경계를 넘어 판 밖으로 나간 기물은 제거된다.
- 운동량·에너지는 충돌마다 보존된다(LAB에서 검증·CSV 내보내기). 반올림으로 생기는 오차는 기록해 탐구 자료로 쓴다.

### 4.4 전략적으로 무엇이 바뀌나 (킥)
- **열린 줄은 레일건이다.** 도움닫기가 길수록 세다. 그러나 빛보다 빠를 수는 없다.
- **벽은 벽이 아니다.** 같은 질량 기물이 일렬로 서 있으면 끝의 하나가 날아간다(뉴턴의 요람). 체스의 "지원"이 물리적으로 다르게 작동한다.
- **가장자리가 위험하다.** 구석의 킹은 안전하지 않다. 킹은 판 중앙의 무게중심을 지킨다 — 체스 직관이 뒤집힌다.
- **질량이 곧 역할.** 폰은 막기엔 가볍고, 퀸은 대포이자 닻이다. 나이트는 유일한 '진짜 잡기'.
- **결과를 보여준다.** 목표 위에 마우스를 올리면 궤적·최종 위치·판 밖으로 떨어질 기물이 미리 보인다(당구의 조준선). 계산은 플레이어 대신 엔진이 하지만, **상대의 다음 충돌**은 직접 읽어야 한다.

## 5. 기술 구조

```
src/
  engine/
    board.ts        # 0x88 또는 64칸 표현, FEN 입출력
    rules.ts        # FIDE 합법수(캐슬링·앙파상·승진·체크·메이트·스테일메이트·50수·3회 반복)
    collide.ts      # 1D 상대론적/뉴턴 탄성 충돌 + 사건 기반 연쇄 시뮬레이션
    variant.ts      # 충돌 체스: 이동 → 충돌 해석 → 링아웃, 체크 판정(시뮬레이션 기반)
    ai.ts           # 알파-베타 + 정지탐색, 변형별 평가 함수
  render/
    assets.ts       # ABeautifulGame 로딩(GLTF+Draco+KTX2), 기물 메시 추출·인스턴싱
    scene.ts        # 보드·카메라·조명, 이동/충돌 애니메이션(실제 시뮬레이션 궤적 재생)
    preview.ts      # 충돌 예측선, 낙하 표시
  ui/               # 타이틀(시작/튜토리얼), HUD, 메뉴, 튜토리얼, 결과, 크레딧
  lab/              # 충돌 실험 화면 + CSV
tests/
  perft.test.ts     # 클래식: perft 1~4 (20 / 400 / 8,902 / 197,281) + 표준 테스트 포지션
  oracle.test.ts    # chess.js와 무작위 1,000국면 합법수 비교
  collide.test.ts   # 운동량·에너지 보존, 저속 극한 = 뉴턴, 광속 미만 보장, 뉴턴의 요람
  variant.test.ts   # 링아웃, 연쇄, 나이트 낙하, 체크/메이트 정의, 캐슬링 제약
```

- **애니메이션 = 실제 시뮬레이션 재생.** 충돌 연출은 엔진이 계산한 사건 목록(시간·위치)을 그대로 재생한다. 가짜 연출 없음.
- 에셋 로딩: 12 MB 압축본 + 로딩 화면. Draco/Basis 디코더는 three.js 패키지에서 `public/`으로 복사.
- 크레딧 화면에 CC-BY-4.0 출처 표기(필수).

## 6. UI · 튜토리얼

- 타이틀: 「시작」「튜토리얼」 (첫 실행 강제 튜토리얼 유지).
- 게임: 상태 한 줄, 아이콘 3개(미리보기 켜기/끄기, 시간 피라미드는 지연 시야 모드에서만, 메뉴), 잡은 기물 트레이.
- 튜토리얼 7단계 (각 1~2수):
  1. 체스처럼 움직인다
  2. 무거운 것이 가벼운 것을 날린다 (룩→폰, 판 밖으로)
  3. 같은 질량은 멈추고 넘겨준다 (뉴턴의 요람 연쇄)
  4. 가벼운 것은 튕겨 나온다 (폰→룩)
  5. 나이트의 낙하 공격
  6. 체크 = 날아갈 위기, 피하거나 막기
  7. 빛보다 빠를 수 없다 (같은 수를 뉴턴/상대론으로 비교해 보여줌)
