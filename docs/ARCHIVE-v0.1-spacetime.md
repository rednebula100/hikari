## 12. 물리 모델의 범위와 수학적 정의

### 12.1 좌표시간, 고유시간, 단위

공간 위치는 `r=(x,z)`, 전장 좌표시간은 `t`, 개별 기물 고유시간은 `τ`이다. 초기 단위계는 `c=1 GU/s`. 이는 실제 빛의 속도를 변경했다고 주장하는 것이 아니라, 광속 대비 길이·시간을 게임 단위로 재스케일링한 모델이다.

기물의 최대 이동 속도는 `0.8c`로 제한한다. 직선 이동 구간은 정속이며 구간 경계에서 방향·속도가 즉시 전환되는 이상화된 운동으로 취급한다. 가속도에 필요한 에너지, 상대론적 운동량과 힘은 초기 모델 범위 밖이다.

### 12.2 세계선

시간 `t0`에 시작해 `t1`에 끝나는 선분의 위치는 다음과 같다.

$$
\mathbf r(t)=\mathbf r_0+\mathbf v(t-t_0),\qquad t_0\le t\le t_1,\quad \|\mathbf v\|<c.
$$

경로의 길이 `d = ||r1-r0||`이고 속력 `v`가 양수이면 이동 시간은 `d/v`이다. 대각선에 맨해튼 거리나 체비셰프 거리를 사용하지 않는다.

정지 구간은 `v=0`의 선분이다. 모든 세계선은 시간 순서로 연속해야 하고 과거 선분을 재작성할 수 없다. 계획 세계선은 별도의 가설 데이터이며 실제 세계선으로 혼합하지 않는다.

### 12.3 인과율과 빛원뿔

사건 `A=(r_A,t_A)`가 사건 `B=(r_B,t_B)`에 영향을 줄 수 있는 필요조건은 다음과 같다.

$$
t_B\ge t_A,\qquad \|\mathbf r_B-\mathbf r_A\|\le c(t_B-t_A).
$$

시공간 간격의 제곱은 부호 관례 `(+,-,-)`에 따라 다음을 사용한다.

$$
s^2=c^2(t_B-t_A)^2-\|\mathbf r_B-\mathbf r_A\|^2.
$$

- `s²>0`: 시간꼴 간격. 아광속 영향 전달이 가능할 수 있음.
- `s²=0`: 빛꼴 간격. 광속 전파 경계.
- `s²<0`: 공간꼴 간격. 직접적인 인과적 영향 전달 불가.

실제 행동 가능성은 명령 도달, 이동 제한, 준비도, 이미 예약된 행동 등의 추가 규칙에 의존한다. `s²≥0`만으로 게임에서 실제 행동이 가능하다고 단정하지 않는다.

2+1차원 시공간에서 미래 빛원뿔의 단면은 `t≥t_A`에서 중심 `r_A`, 반경 `c(t-t_A)`인 원이다. 과거 빛원뿔은 `t≤t_A`에서 반경 `c(t_A-t)`인 원. 화면의 시간축 스케일을 변경해도 원의 실제 반경과 계산은 변하지 않는다.

### 12.4 움직이는 수신기의 신호 도달

발신 사건 `(s,t_e)`에서 시작한 신호의 앞 전면과 수신기의 세계선이 만나는 최초 시간을 구한다.

$$
\|\mathbf r_{receiver}(t)-\mathbf s\|=c(t-t_e),\qquad t\ge t_e.
$$

수신기의 현재 선분이 `t_b`에서 시작하고 `r_b`를 통과하며 속도 `v`를 가진다고 하자. `u=t-t_b`, `q=r_b-s`, `δ=t_b-t_e`로 놓으면 다음 이차방정식이 된다.

$$
(\mathbf v\cdot\mathbf v-c^2)u^2
+2(\mathbf q\cdot\mathbf v-c^2\delta)u
+(\mathbf q\cdot\mathbf q-c^2\delta^2)=0.
$$

실근 가운데 다음 조건을 만족하는 가장 이른 시간을 선택한다.

- 현재 선분 범위 내.
- 발신 시각 이후.
- 이미 신호를 수신한 기록 없음.
- 원래 제곱하지 않은 거리식과 허용 오차 범위에서 일치.

수신기 경로가 변하면 앞으로의 교차 후보를 새로 계산한다. 아직 결정되지 않은 이동 경로를 실제 경로처럼 사용하지 않는다. 동일 좌표 발신은 전파 시간 0을 허용하되 이벤트 정렬 정책으로 무한 재귀를 방지한다.

고정 수신기는 `t_e + d/c`로 계산한다. COMMAND와 TELEMETRY는 초기 엔진에서 길이 0의 정보 이벤트로 처리한다. DATA와 PHASE는 유한한 수신 윈도우를 가진다.

### 12.5 고유시간 적분

$$
\Delta\tau=\int_{t_0}^{t_1}\sqrt{1-\frac{\|\mathbf v(t)\|^2}{c^2}}\,dt.
$$

정속 선분에서는 다음과 같이 정확하게 계산할 수 있다.

$$
\Delta\tau=\Delta t\sqrt{1-\beta^2},\qquad \beta=\|\mathbf v\|/c.
$$

세계선을 선분별로 나눠 고유시간을 합산한다. 모든 준비도와 로컬 cooldown은 실제 고유시간 누적값을 사용한다. 화면에 표시된 프레임 시간이나 라운드 횟수를 사용하지 않는다.

### 12.6 파동 전파 및 위상

초기 모델은 2D 공간에 놓인 파원에서 유한 펄스를 방출하는 **스칼라 파동의 단순화된 현상론적 모델**이며 Maxwell 방정식의 완전한 해나 2D 파동 방정식의 정확한 점파원 해라고 주장하지 않는다.

고정 파원 `i`의 발신 시각 `t_i`, 위치 `s_i`, 발신 위상 `φ_i`, 발신 진폭 `A_i`, 펄스 길이 `L_i`, 거리 `d_i=||r-s_i||`를 사용한다.

$$
q_i(t,\mathbf r)=t-t_i-d_i/c,
$$

$$
\psi_i(\mathbf r,t)=\frac{A_i}{1+d_i/2}\,g_i(q_i)\cos(\omega q_i+\phi_i),\qquad \omega=2\pi f.
$$

`g_i(q)=1` for `0≤q<L_i`, otherwise `0`인 이상적인 사각 펄스 포락선을 초기 판정에 사용한다. 시각적으로 경계를 부드럽게 보간할 수 있으나 파동 전면보다 앞선 구간에 물리 신호를 표시하지 않는다. 수신 판정과 시각 표현의 차이가 생기지 않도록 기본 정밀 분석 뷰에서는 동일 포락선을 사용한다.

동일 채널의 스칼라 파동 표시값은 다음과 같다.

$$
\psi(\mathbf r,t)=\sum_i\psi_i(\mathbf r,t).
$$

공간 파동이 합쳐졌다가 다시 분리되어 보이는 것은 정상이다. 한 지점의 상쇄를 이유로 원래 펄스의 이후 전파를 제거하지 않는다. 시각 필드에서 복수 파원을 합산하는 것과 게임에서 데이터 패킷별 파일럿을 독립 평가하는 추상화의 차이를 범례 및 인스펙터로 구분한다.

### 12.7 정지 수신기의 파일럿 간섭 판정

초기 전술 판정은 정지 수신기와 동일 주파수의 이상적인 결맞는 파일럿 모델이다. 이동 파원/수신기의 완전한 상대론적 도플러 효과, 편광, 실제 변조·부호화는 포함하지 않는다.

수신기까지의 전파 시간까지 포함한 각 펄스의 앞 전면 도달시간을 `a_i=t_i+d_i/c`로 놓으면, 공통 반송파 `exp(iωt)`에 대한 복소 진폭은

$$
z_i(t)=a(d_i)\,g_i(t-a_i)e^{\mathrm i(\phi_i-\omega a_i)}.
$$

여기서 진폭 함수는 `a(d_i)=A_i/(1+d_i/2)`이며 앞 전면 도달시각 `a_i`와는 별개의 값이다. 코드에서는 각각 `attenuatedAmplitude`와 `arrivalTime`으로 명명하여 혼동을 방지한다.

목표 DATA의 복소 진폭을 `z_D`, 해당 수신기와 채널에 지정된 모든 PHASE 펄스를 `z_J`라 할 때

$$
Z(t)=z_D(t)+\sum_J z_J(t).
$$

정규화 수신 진폭은 데이터 수신 윈도우 `W=[arrival_D,arrival_D+L_D)`에서 다음과 같다.

$$
R=\frac{1}{L_D A_{D,rx}}\int_W|Z(t)|\,dt.
$$

`R<0.40`이면 실패, `R≥0.40`이면 성공이다. 여기서 `A_D,rx`는 간섭이 없을 때 해당 파일럿의 수신 진폭이다. 위상과 진폭이 동일하면 `R=2`, 위상차 180°·동일 진폭·완전 겹침이면 `R=0`, 펄스가 겹치지 않으면 `R=1`이 된다.

사각 포락선과 정지 수신기를 사용하므로 윈도우 내 모든 펄스의 시작/종료 경계를 모아 구간별 상수 복소 진폭을 계산하면 적분을 정확하게 수행할 수 있다. 렌더링 프레임에 의존하는 근사 샘플링이 필요하지 않다.

이 값은 실제 통신의 BER(비트 오류율)이나 에너지 효율이 아니다. 큰 반대 위상 펄스가 지나치게 크면 `|Z|`가 다시 커질 수 있으며, 이는 의도적으로 도입한 '정밀 상쇄' 게임 규칙의 성질이다. 일반적인 잡음 재밍을 완전 모사한다고 주장하지 않는다.

### 12.8 수학적 간섭 예제 (개발 기준)

수신기 `(4,4)`에 데이터 파원 `(0,4)`에서 `t=0`, 진폭 1, 위상 0°의 0.5초 펄스를 발신한다. 거리 4, 수신 윈도우 `[4,4.5)`.

PHASER가 `(6,4)`에서 `t=2`, 발신 진폭 2/3, 위상 180°의 펄스를 보낸다면 거리 2, 도달시간 4, 두 수신 진폭 모두 1/3이 된다. 동일 주파수와 도달시각이므로 이상적 상쇄가 성립한다.

이는 연속 진폭을 허용하는 LAB 검증용 예제이다. 실전에서는 진폭 단계 `0.5/1/2`를 사용하므로 완전 상쇄가 항상 가능하지는 않다. 예를 들어 진폭 0.5를 사용하면 수신 진폭은 1/4, 합성 파일럿의 상대 진폭은 0.25로 초기 임계값 아래에 해당한다. 명령의 실제 도달 및 준비도 조건은 별도로 충족해야 한다.

### 12.9 제외하는 물리와 확장 방향

| 초기 구현 | 추후 검토 대상 |
|---|---|
| 공통 관성계 좌표시간과 고유시간 | 관성계 전환과 로런츠 변환 인스펙터 |
| 유한 신호 전파·빛원뿔 | 상대적 동시성의 직접적 시각화 |
| 정지 파원의 스칼라 간섭 | 움직이는 파원·수신기의 상대론적 도플러 |
| 직선 아광속 이동 | 유한 가속, 상대론적 운동량·에너지 |
| 2D 공간+1D 시간 | 별도의 다차원 공간 전장 확장 |

상대적 동시성과 관성계 전환은 학문적으로 중요한 개념이지만 현재 핵심 게임 규칙과 구분한다. 공통계에서 고유시간과 인과율을 계산하는 모델만으로 특수 상대론의 모든 효과가 구현되었다고 표현하지 않는다. 향후 관성계 변환은 같은 사건들을 다른 좌표로 표시할 뿐 게임 결과를 변경하지 않아야 한다.

## 13. 소프트웨어 아키텍처

### 13.1 기술 스택 초기안

- TypeScript (strict), Vite, React 또는 동급의 경량 UI 프레임워크, Three.js.
- WebGL2 기반 3D 렌더링. 의존성은 버전 고정 및 lockfile 관리.
- Vitest 또는 동급의 단위/통합 테스트, Playwright 또는 동급 브라우저 E2E 테스트.
- 초기 저장·공개: 정적 빌드, 로컬 저장 및 JSON 내보내기. 사용자가 원하면 GitHub Pages 배포 가능한 구조. 비밀 키가 필요한 외부 API는 필수 의존성으로 만들지 않는다.
- 초기 AI는 로컬 결정론적 전략 알고리즘. LLM API를 게임 기본 동작에 사용하지 않는다.
- 기존 프로젝트의 코드나 에셋을 기본적으로 재사용하지 않는다. 새로운 프로젝트로 독립 구현하며 외부 코드 사용 시 라이선스를 기록한다.

```ts
  id: string;
  t: number;
  kind: string;
  entityId?: string;
  parentIds: readonly string[];
  payload: unknown;
}>;

type ObservedUnit = Readonly<{
  unitId: string;
  observedAt: number;
  receivedAt: number;
  position: Vec2;
  velocity: Vec2;
  status: 'observed' | 'confirmed';
}>;

type PlayerView = Readonly<{
  team: Team;
  coordinateTime: number;
  ownScore: number;
  lastReportedEnemyScore: number;
  observations: readonly ObservedUnit[];
  knownEvents: readonly SimEvent[];
  ownSubmittedPlans: readonly unknown[];
  // 실제 구현에서 unknown을 검증된 discriminated union으로 대체
}>;
```

`TruthState`, `PlayerView`, `HypothesisState`, `ReplayState`는 타입과 모듈 경계를 분리한다. 실제 타입은 모든 명령과 이벤트를 discriminated union으로 구현하고 입력 JSON을 런타임 검증한다.

### 13.4 결정론적 이벤트 엔진

권장 방식은 **연속 정속 선분 + 이벤트 기반 진행**이다. 이동 및 신호 도달은 해석적으로 계산하고, 렌더러는 해당 시간의 상태를 보간한다. 고정 프레임 또는 실제 브라우저 경과 시간에 게임 규칙을 종속하지 않는다.

기본 이벤트 종류:

- 명령 발신 / 명령 도달 / 로컬 행동 실행
- 이동 시작 / 이동 종료 / 준비 완료
- 관측 신호 발신 / 수신 / ACK 수신
- NEXUS 점령 변경 / 생산 완료
- DATA 전파 및 수신 윈도우 시작 / 종료 / 전달·실패
- PHASE 발신 및 수신기 도달 구간 경계
- RELAY 처리 완료 / 재발신
- 라운드 종료 / 매치 종료

이벤트 큐는 `(timeKey, priority, stableId)` 순으로 정렬한다. 내부 시각은 최소 1µs 수준의 고정 소수점 키 또는 동등한 재현 가능한 정규화 정책을 사용한다. 물리식 계산은 double precision으로 하되 허용 오차와 동일 시각 묶음 정책을 문서화한다.

같은 시각에 발생한 양측 사건을 진영 ID 순서로 순차 판정해 편향을 만들지 않는다. 동일 시각의 이벤트를 묶고 공통 스냅샷 기준으로 상태 변화를 처리한다. 다음 순서를 명시적인 계약으로 유지한다.

1. `t` 직전까지의 모든 이동·고유시간·점령 진행을 적분한다.
2. 동일 시각의 이동 완료, 준비 완료, 신호 수신 완료 등 도달 사건을 수집하고 동시에 반영한다. 이전 수신 윈도우는 반개구간 `[start,end)`으로 종료한다.
3. 명령 도달 및 명령 교체, 로컬 행동 시작, 이동·발신·중계 이벤트를 공통 스냅샷에 대해 평가한다. 새로 발신된 0거리 신호는 동일 시각의 다음 마이크로스텝으로 처리한다.
4. 점령 가능 상태와 생산 완료를 재평가한다. 기본 규칙은 **직전 구간에서 3초의 생산을 완료한 데이터는 생성**하고, 같은 시각 도착한 적 기물은 이후 생산을 방해한다. 경계 직전의 연속 점령 시간이 충분하지 않으면 생성하지 않는다.
5. 신규 데이터와 관측 이벤트를 발신하고 후속 이벤트를 스케줄링한다. 점수는 수신이 완료된 시각에만 갱신한다.
6. 라운드/매치 경계에서는 해당 시각에 완료된 득점과 모든 예정 이벤트의 처리 규칙을 적용한 후 상태를 고정한다. 매치 종료 시 새 발신은 진행하지 않는다.

위는 초기 동시성 규약이다. 구현 중 경계 조건이 더 세분화될 경우 테스트와 함께 명세를 수정한다. 반복 가능한 `same-time` 이벤트는 처리 횟수 한계와 순환 방지 조건을 둔다. 중계 홉 제한과 동일 패킷 수신 ID 중복 방지가 필수이다.

### 13.5 이벤트 취소와 재계산

이동 경로 변경 또는 새 상태로 인해 아직 일어나지 않은 신호 교차 후보가 무효가 되면 generation ID로 이전 예약을 무효화하고 새 교차를 계산한다. 이미 실행한 이벤트나 발신한 신호는 삭제하지 않는다.

수신기 이동 시작으로 데이터 수신이 실패하거나 중계 예약이 무효화되는 경우 명시적인 실패 이벤트를 남긴다. 과거 로그를 수정해서 실패를 감추지 않는다.

### 13.6 렌더링과 물리 일치

- 공통 `positionAt(unitId,t)` / `tauAt(unitId,t)` / `waveAt(r,t,channel)` 정의를 공유한다. GPU 파동 셰이더는 동일 수식·파라미터의 시각 경로이다.
- 셰이더와 CPU 함수에 같은 입력을 주어 샘플 값이 허용 오차 내 일치하는지 검증한다. GPU 정확도 부족은 시각 품질만 변경하며 게임 판정은 CPU 권위 경로로 유지한다.
- 시공간의 미래 궤적은 실제 엔진을 복제한 가설 상태에서만 계산한다. 실제 적 명령이나 미공개 관측을 섞지 않는다.
- 물리 엔진은 프레임 렌더링 없이도 전체 경기, 리플레이, LAB 실험을 실행할 수 있어야 한다.

# PART VI — SCIENTIFIC INQUIRY / VALIDATION

## 16. 독립적인 물리학 탐구

### 16.1 연구 배경 및 목적

잠정 주제:

**특수 상대성 이론의 인과적 제약과 파동의 간섭이 정보 전달 시스템에 미치는 영향 — 시공간 전략 게임의 물리 모델을 활용한 탐구**

게임의 구현 자체와 물리 모델의 과학적 검증은 서로 구분한다. 본 연구에서는 특수 상대론적 인과성과 유한 펄스의 간섭 모델에 대해 독립적인 이론 분석, 수치 검증 및 통제된 실험을 수행한다. 연구 결과는 재현성과 모델의 적용 범위를 기준으로 평가한다.

핵심은 다음 연구 질문이다.

- 신호의 유한한 전파 속도와 수신기의 이동 속도가 정보 전달 시각에 어떤 영향을 미치는가?
- 이동 경로의 속도에 따라 같은 좌표시간 동안의 고유시간이 어떻게 달라지는가?
- 파동의 위상차·진폭·도달 시차에 따라 수신 지점의 합성 진폭이 어떻게 변하는가?
- 위 조건이 결합된 정보망에서 어떤 구조와 타이밍이 통신 성공에 영향을 미치는가?

### 16.2 LAB A — 신호와 움직이는 수신기

독립변인: 수신기 속도(정지, 0.2c, 0.4c, 0.6c, 0.8c), 초기 거리, 이동 방향. 통제: 송신 위치·시각, 광속. 종속변인: 도달 시각, 도달 위치, 이론값과 구현값 오차.

1차원에서 초기 거리 `d`인 수신기가 같은 방향으로 일정 속도 `v`로 움직이면 `t=d/(c-v)`. 접근 방향은 `t=d/(c+v)`. 실험 UI는 시간축 그래프와 세계선 교차를 함께 표시한다. 2차원 이동 사례로 확장하고 수치 오차를 측정한다.

### 16.3 LAB B — 고유시간

독립변인: 속도와 이동 구간 조합. 통제: 좌표시간 또는 경로 길이(둘은 서로 다른 실험으로 분리). 종속변인: 고유시간, 상대론적 시간 지연 비율.

고정 좌표시간 실험의 이론값: `τ/t = sqrt(1-β²)`. 0.8c에서 0.6, 0.6c에서 0.8. 서로 다른 경로를 비교할 때는 정지 구간까지 포함하여 전체 고유시간을 계산한다. 실전 Courier 준비도 결과는 물리량과 별도 게임 변인으로 구분한다.

### 16.4 LAB C — 파동 간섭

독립변인: 위상차, 진폭비, 펄스 도달 시차. 통제: 주파수, 수신기 위치, 펄스 길이. 종속변인: 합성 진폭, 정규화 파일럿 값 `R`.

같은 주파수의 두 파동이 완전히 겹치는 경우의 이론 진폭:

$$
A_R=\sqrt{A_1^2+A_2^2+2A_1A_2\cos\Delta\phi}.
$$

동일 진폭 `A`이면 `A_R=2A|cos(Δφ/2)|`. 위상차를 0°부터 360°까지 연속 또는 일정 간격으로 변화시키고 이론 곡선과 구현 결과를 비교한다. 다음 실험으로 펄스 겹침 길이를 변화시켜 `R`에 미치는 영향을 분석한다.

상쇄 간섭은 수신 지점의 파동 진폭이 줄어드는 것이지 우주 전체의 에너지가 소멸하는 것을 뜻하지 않는다. 초기 스칼라 모델은 실제 전자기장의 에너지 보존을 완전하게 계산하지 않으므로 전역 에너지 보존을 입증한다고 주장하지 않는다.

### 16.5 LAB D — 정보망의 결합 실험

고정 위치의 송신기, 수신기, 중계기와 방해 파원을 배치한다. 직접/중계/중복 경로별 전달 지연과 성공 여부를 비교한다. 동일한 데이터 생성 시각과 방해 조건을 통제한다. 방해 조건을 변화시키는 실험은 결정론적 파라미터 격자 또는 기록된 seed를 사용한다.

측정할 항목: 최소 전달 시각, 중복 전송 비용, 설정한 방해 사례에서의 성공률. `성공률`은 실험한 사례 집합에 대한 비율이며 현실 통신망의 신뢰도 추정치가 아니다.

### 16.6 선택적 LAB E — 로런츠 변환

핵심 게임의 안정성이 확보된 뒤 구현 검토. 관성계 속도 `u`가 x축 방향인 경우 `γ=1/sqrt(1-u²/c²)`와 다음 관계를 사용한다.

$$
x'=\gamma(x-ut),\qquad t'=\gamma(t-ux/c^2),\qquad z'=z.
$$

동일 사건들의 시공간 간격과 빛원뿔을 서로 다른 관성계에서 비교한다. 시간 지연뿐 아니라 동시성의 상대성까지 탐구할 수 있으며, 관성계 전환 전후의 게임 상태가 동일해야 한다. 초기 모델에 포함되지 않으면 보고서에 구현했다고 작성하지 않는다.

### 16.7 결과 기록 요구사항

- 실험 실행 ID, 게임/엔진 버전, 독립변인·통제변인, 이론값, 구현 결과, 오차, 실행 시각을 저장.
- CSV/JSON 내보내기. 그래프는 기록된 데이터에서 생성한다.
- 이론 예상값과 실측 시뮬레이션 결과를 다른 열로 구분한다.
- 실험을 아직 수행하지 않았으면 결과 대신 가설·방법만 표시한다.
- 기술 연구 보고서에는 모델의 근사, 적용 범위, 물리적 한계, 개선 방향을 포함한다. 개발 및 분석에 사용한 도구와 자동화 절차는 재현성 확보를 위해 실제 사용 내역을 기록한다. 허위 실험 기록을 생성하지 않는다.

### 17.3 시각 및 브라우저 테스트

- 모든 소켓 선택, 카메라 각도에 따른 피킹, 중복 위치 기물 선택.
- SPATIAL↔SPACETIME↔WAVE의 반복 전환, 도중 취소, Reduced Motion.
- 시공간 뷰의 단면 시간과 세계선 위치의 실제 엔진 일치.
- 시간 스크럽 중 실제 게임 시간 및 점수 불변.
- 비공개 정보가 렌더링 애니메이션, 툴팁, 이벤트 소리로 누출되지 않음.
- 1366×768, 1920×1080, 2560×1440, 1280×720에서 HUD 겹침과 `html/body` 오버플로 확인.
- 브라우저 리사이즈, 탭 비활성화/복귀, WebGL 컨텍스트 손실 시 안전한 복구 또는 오류 안내.
- 품질 설정 변경 후 게임 판정 동일.
- 콘솔 에러, 메모리·GPU 리소스 누수, 반복 전환 후 이벤트 리스너 중복 여부 확인.

60fps는 권장 목표이며 범용 데스크톱과 일반 노트북의 실측 결과에 따라 조정한다. 테스트하지 않은 하드웨어에서 일정 성능을 보장하지 않는다. 성능보다 게임 규칙과 가독성을 우선하고 시각적 품질 저하 모드를 제공한다.
